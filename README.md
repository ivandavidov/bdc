# BDC Радар

**Сайт:** https://ivandavidov.github.io/bdc/

Статичен сайт на български, който оценява борсово търгуваните **Business Development Companies (BDC)** в САЩ по едни и същи правила:

- дивидентна устойчивост;
- стабилност на NAV;
- кредитно качество;
- задлъжнялост;
- разходи.

Всяка компания получава оценка за качество 0–100 и светофар (Силна / Средна / Слаба). Ценовото ниво (P/NAV спрямо собствената 3-годишна история) е отделно: качеството и евтиността не се смесват.

Данните идват само от публични източници (SEC EDGAR и Yahoo Finance). GitHub Actions ги обновява автоматично всеки делничен ден.

> Информацията на сайта не представлява инвестиционен съвет. Изчисленията са автоматични и може да съдържат грешки.

## Какво има в сайта

| Страница | Съдържание |
|---|---|
| `index.html` — Табло | Обобщение на сектора, таблица с всички BDC (сортиране, филтри, групи колони), ★ списък за наблюдение, отметки за сравнение, графика „Качество спрямо P/NAV“, последни промени |
| `company.html?t=ARCC` — Профил | Оценка за качество и разбивка, предупреждения, ключови показатели с персентили, графики (цена/NAV, P/NAV, NII срещу дивидент, покритие, доходност на NAV, необслужвани заеми, задлъжнялост, PIK), портфейл, акционери, дивиденти, такси, отчети в SEC |
| `compare.html` | До 4 компании една до друга + наслагнати графики |
| `sector.html` | Секторни медиани във времето; здраве на портфейлите (обезценки, необслужвани заеми, PIK, доходност, кредитополучатели с проблеми при няколко BDC); класации |
| `changes.html` + `feed.xml` | Дневник на важните промени и RSS |
| `methodology.html`, `learn.html`, `glossary.html` | Методология, „Какво е BDC“, речник |

## Как се изчислява оценката

Пълното описание е на страницата „Методология“, която се генерира от [`config/scoring.yaml`](config/scoring.yaml). Накратко:

- Всеки показател получава от 0 до 100 точки по опорни стойности, между които се интерполира линейно. Категориите имат тегла: дивидент 25, NAV 25, кредит 20, ливъридж 15, разходи 15.
- **Най-слабо звено:** ако дивидентът, NAV или кредитното качество са под 25 точки, светофарът е червен, каквото и да е средното.
- **Предупреждения** (например съкратен дивидент, спад на NAV над 10%, покритие на дълга с активи под 170%): 1–2 предупреждения ограничават светофара до жълто, 3 и повече го правят червен.
- Ако липсват данни за над 30% от теглото, компанията се отбелязва като „Непълни данни“ и не се класира.

## Откъде идват данните

| Данни | Източник |
|---|---|
| Списък с компании | SEC BDC Data Sets (всички BDC с XBRL отчети) ∩ файлът на SEC с тикери на NYSE/Nasdaq → `config/universe.yaml` |
| Финансови отчети | SEC XBRL API (`data.sec.gov/api/xbrl/companyfacts`); таговете по показател са в `config/xbrl_tags.yaml` |
| Портфейл и необслужвани заеми | Schedule of Investments от XBRL на всеки 10-Q/10-K чрез [edgartools](https://github.com/dgunning/edgartools); типовете инвестиции се групират по `config/investment_types.yaml` |
| Цени и дивиденти | Yahoo Finance чрез `yfinance` |
| Акционери | Yahoo Finance (по 13F отчети, със закъснение 1–3 месеца) |

## Локално пускане

Нужен е Python 3.10+ (edgartools не работи с 3.9). С [uv](https://github.com/astral-sh/uv):

```bash
brew install uv
```

```bash
uv venv -p 3.12 .venv && uv pip install -p .venv -r requirements.txt
```

SEC изисква контакт в User-Agent:

```bash
export SEC_USER_AGENT="bdc-radar your@email.com"
```

Изграждане на данните. Първият път отнема ~20–30 минути заради портфейлите, после всичко се кешира в `data_cache/`:

```bash
.venv/bin/python -m pipeline.build
```

Преглед на сайта на http://localhost:8000:

```bash
python3 -m http.server 8000 --directory docs
```

Тестове:

```bash
.venv/bin/python -m pytest -q
```

Отчет за качеството на данните (липсващи показатели, покритие на портфейлите, неразпознати типове инвестиции):

```bash
.venv/bin/python -m pipeline.report
```

Полезни опции на `pipeline.build`:

- `--skip-universe` — не обновява списъка с компании;
- `--only ARCC MAIN` — само тези тикери, за отстраняване на грешки (не презаписва общите файлове);
- `--portfolio-history 8` — за колко последни отчета да се изчисли историята на необслужваните заеми (по подразбиране 4).

## Автоматично обновяване

Workflow-ът [„Обновяване на данните“](.github/workflows/update-data.yml) върви в 22:30 UTC в делнични дни. Той пуска тестовете, изгражда данните и commit-ва `docs/data`, `docs/feed.xml` и `config/universe.yaml`. Може да се пусне и ръчно от **Actions → Run workflow**.

## Собствено копие

1. Направете fork или ново хранилище с този код.
2. **Settings → Pages → Build and deployment:** Source = *Deploy from a branch*, Branch = `main`, папка `/docs`.
3. **Settings → Secrets and variables → Actions:**
   - Secret `SEC_USER_AGENT` = `bdc-radar your@email.com`;
   - по желание Variable `SITE_URL` = адресът на сайта, ако не е стандартният `https://<потребител>.github.io/<repo>/` (ползва се за RSS линковете).
4. **Actions → „Обновяване на данните“ → Run workflow** за първото пускане.

## Настройки

- **`config/universe.yaml`** — допълва се автоматично. Ръчно могат да се зададат `manager`, `managed: internal|external`, `exclude: true` (за изключване на компания) и `note`. Ръчните полета се запазват при обновяване.
- **`config/scoring.yaml`** — категории, тегла, прагове, предупреждения и прагове за ценовото ниво.
- **`config/xbrl_tags.yaml`** — ако някоя компания маркира показател с различен таг, добавете го в списъка.
- **`config/investment_types.yaml`** — правила за групиране на типовете инвестиции.

## Известни ограничения

- XBRL маркирането се различава между компаниите, затова някои показатели липсват при някои BDC. Те се показват с „—“, а оценката преразпределя теглата.
- Историята на необслужваните заеми започва от 2025 г., защото се натрупва от отчетите напред във времето.
- Отрасълът на инвестициите рядко е маркиран в XBRL, затова разпределението по отрасли почти липсва.
- Имената на кредитополучателите с проблеми при няколко BDC се съпоставят автоматично и списъкът може да е непълен.
- Редовните и специалните дивиденти се разделят евристично по плащанията в Yahoo. При компании с променлив допълнителен дивидент разделянето е по-неточно.
- `yfinance` е неофициално API. При неуспех се ползва последната кеширана цена и профилът показва предупреждение.
